# Security and business integrity (phase 4 as-built)

Source is authoritative. This phase hardens the existing Bun/Elysia platform; it does not activate QRIS, change editor documents, or prove live vendors. Read together with [deployment](deployment.md), [workers](workers.md), [testing](testing.md), and the phase-4 report.

## Auth and request boundary

- JWT is httpOnly/SameSite=Lax; Secure in production. HS256 only, UUID subject/session IDs, issued/expiry claims required. DB session must belong to subject and remain unexpired. Role comes from users, never JWT/browser role. Disabled login is rejected; financial refunds remain possible.
- Session creation/enforcement holds a users row lock. Expired sessions do not consume a slot. Free default1, effective plan limit/null supported. Active and canceled periods require start <= now < end. Null dates grant no access. `/sessions` reports the actual current session ID.
- Unsafe production browser requests require an exact CLIENT_URL/ADMIN_URL Origin. Cross-site origins are denied; SameSite is additional protection. Only Stripe/Pakasir signed callback boundaries are exempt, and handlers must authenticate callbacks. CORS uses the same configured origins.
- Main Compose injects TRUST_PROXY=1 into the private app. Nginx overwrites forwarding headers. Standalone default ignores XFF. Do not expose app3000 or share its trusted network with untrusted workloads. Rate limiting uses validated single IPs, bounded buckets, global200/min and auth/billing30/min. It is process-local; replicas require a shared limiter before scaling.
- Google endpoints: GET `/api/auth/google?returnTo=/account`, GET `/api/auth/google/callback`. Exact GOOGLE_REDIRECT_URI must match the Google console; configure both client credentials. Server stores a hashed one-use state plus cookie binding, encrypted PKCE verifier, nonce and10-minute expiry. Fixed Google authorization/token/JWKS endpoints; signed RS256 identity checks issuer/audience/time/nonce/verified email and stable sub. No password-account auto-link by email; account-link conflict409 requires an explicit future linking flow. No access/refresh token is persisted or returned. UI integration is phase7. Offline cryptographic/state tests passed; actual Google exchange/consent remains untested.

## Credits and subscriptions

`withUserTransaction` locks an existing users row, including the empty-ledger case. Credits have a stable account plus lots, allocations and immutable ledger entries. Every financial mutation updates these together under that lock. Direct ledger inserts by application routes have been removed; do not write balances with ad-hoc SQL.

First access imports an aggregate only when legacy SUM(delta) matches an admissible latest balance and is nonnegative. Otherwise CREDIT_RECONCILIATION409: history is preserved, no account is created. Admin list may report null balance for this explicit reconciliation state. No guessed repair or retrospective expiry. Imported legacy lots have no expiry because existing data cannot prove an expiry date.

New server snapshots store plan/pack benefits with the pending order. Managed subscription quota is granted once per current UTC calendar month, lazily on credit access/usage; missed months are not accumulated. Annual billing still grants monthly quota. End-of-month anchors clamp February without drifting future months. New top-up expires at the current subscription credit-period end, or one calendar month after purchase without a subscription. Debit consumes earliest-expiring lots. Refund requires an exact original charge and restores only unexpired allocations; duplicate refund has no further effect. Expiry is auditable, not silent balance reset.

Canceled plans retain rights until period end. Same-benefit paid renewal extends from the original calendar anchor and grants no extra quota for the current month. Overlapping plan/cycle changes, changed benefits and legacy/manual renewal require operator reconciliation; no implicit proration. Manual admin subscription keeps quota0 to preserve existing no-auto-credit behavior; use a separately authorized idempotent adjustment if appropriate. Admin adjustment only uses reason admin_adjust, requires Idempotency-Key and cannot produce a negative balance. Admin HTTP client supplies a request key.

## Payments and legacy history

New legacy Stripe/Pakasir checkout is503, never a simulation. Production stub checkout/dev-pay/provider is forbidden even if allow flags are true. Only nonproduction with explicit ALLOW_PAYMENT_STUB=true or ALLOW_AI_STUB=true and clearly named stub-/sample-/demo- provider may simulate. Unsigned stub webhook always fails.

Stripe raw body HMAC-SHA256/timestamp tolerance300s is verified with STRIPE_WEBHOOK_SECRET. Only supported paid checkout events are interpreted; tampered/old/unpaid/unknown events never grant. Pakasir callback has no verified contract, so fails closed. The webhook secret enables history ingestion, not new Stripe checkout. Legacy API keys are not repurposed for QRIS.

`payment_events` durably records sanitized verified receipts before fulfillment. Reusing event IDs with different content fails. `payment_receipts` makes a physical `(provider,gatewayRef)` unique across users/orders. Exact gateway/ref/currency/amount must match. Pending -> paid, subscription/credit/license grants and fulfillment marker share one DB transaction. If fulfillment fails, order stays pending, receipt stays received for retry. No browser-supplied amount/paid flag can settle an invoice.

Migration0004 marks ALL historical orders as legacy_review without changing their gateway, status, amount, or history. Verified callbacks for these return202 review_required without replaying benefits. This intentionally prevents both double credit and guessing what prior code already granted. There is no automatic manual-override endpoint. QRIS invoice/matching/unique codes/late payments and receipt worker are phase5, still unavailable.

Recovery: inventory received/review_required receipts, compare merchant/provider receipt against order/items, ledger, subscription, licenses and historical grants; record an operator decision and backup before any separately reviewed data repair. Never clear a marker and blindly replay. Old pending orders lacking snapshots require an explicit reconciled snapshot and proof of outstanding benefits. Do not reclassify historical gateways/currencies.

## AI jobs and worker

Pro AI tier/priority follows the existing proTemplates capability, so an effective Free Basic row remains Free. API validates model/feature/tier/cost and image inputs server-side, serializes one active job/user, and commits debit + pending job + SQL outbox together. Optional Idempotency-Key reuses the same request/hash; a changed payload conflicts. Accepted jobs return202. No Redis availability is needed to commit the durable job. Pending cancellation endpoint refunds once before processing; it does not cancel an already submitted remote call.

Independent worker runs dispatch/recovery every5s. BullMQ jobId equals DB UUID. Outbox SQL rows are locked SKIP LOCKED; failed delivery remains pending. Delivery retries every30s also recover pending jobs after Redis loses data. A SQL claim changes pending -> processing with a5-minute lease. Terminal redelivery never calls the provider. A failed Redis entry is retried only while SQL still says pending; before first Redis connection the producer fails fast without waiting inside a SQL transaction. Accepted remote provider references are persisted; unconfirmed submit/poll failures and expired processing are failed/refunded with needsReview, never blindly resubmitted; pending timeout30min releases credit. Legacy active jobs without reservation metadata are marked for review, with no fabricated refund. Operators must drain/reconcile these before cutover.

This proves one financial effect in DB, not exactly-once execution at the external vendor. A worker crash after remote submission may leave a remote bill/result that needs reconciliation. Redacted errors are intentional. Worker shutdown waits maintenance and active jobs, then closes queue/DB. Redis must be durable and monitored independently; outbox preserves dispatch, not Redis infrastructure itself.

Configured legacy AI adapter also needs AI_LEGACY_ADAPTER_ENABLED=true in production. It remains disabled by default: its generic vendor contract is not live-verified. Explicit AI_PROVIDER_HOSTS permits exact HTTPS hostnames only, with no credentials/query/fragment/private DNS. All DNS answers must be public, TLS connection is pinned to a validated address, redirects refused, DNS/request timeouts and response limits apply. IPv4 is preferred; single-address lookup disables autoSelectFamily. AI_INPUT_HOSTS and AI_RESULT_HOSTS separately permit public storage/results (signed query allowed). Raster data inputs are decoded/validated and bounded. No fallback to another model/vendor is invented. A credential-free example.com HTTPS probe verifies Bun compatibility, not vendor behavior.

## Assets, storage, projects and admin

Public list/detail/bundle items expose only published metadata and no original keys. Authenticated editor loader requires DB admin role, permanent license, or published subscription asset with matching editor/tier rights. Owned archived assets remain available; no public-preview/original HTTP fallback. Store price/claim/draft checks publication, marketplace flag, complete unique ID sets and server prices. Claims are serialized/unique. Old store checkout remains an explicitly pending draft; actual QRIS checkout unification follows phases5/7.

Project CRUD preserves the scene JSON format and always checks ownership. 3D mutations require editor entitlement or a licensed model; existing owned data remains readable. Thumbnail must be owned/admin-approved media. Size limits and UUID validation apply. Local project export/save-load renderer tests remain phase8/9; serialization regression passed.

Uploads remain admin-only. Limits: preview25MiB, product100MiB, gateway110MiB. Raster decode/pixel limit/Sharp thumbnail; binary signatures for supported formats; GLB header/chunk bounds and contained glTF resources. Claimed browser MIME is not trusted. SVG/script, malformed raster and external-resource glTF are rejected. This is not a full glTF accessor/render/malware validator; phase8 performs glTF2 validation. ZIP/font/video get format checks and are never executed/extracted server-side. Original and thumbnail media record owner and validated MIME; random UUID names prevent collisions. Storage writes are cleaned if metadata transaction fails.

Keys reject traversal, schemes, control characters and encoded delimiters. Local paths reject symlink components and remain within storage root; storage volume must be writable only by trusted app operators. HMAC expiry/token comparison is constant-time; local download cache cannot exceed token expiry. Validated passive MIME uses nosniff/CSP sandbox; unknown/legacy content is attachment/octet-stream. R2 bucket must remain private with narrowly configured CORS, signed expiring GET and no public original URLs. Managed R2/CORS behavior remains untested.

New admin metadata validates nonnegative money/two decimals, safe keys, bounded media URL and slug fields. Existing rows are not mass-rewritten. Unsafe legacy URLs/keys must be inventoried/reuploaded rather than bypassing authorization. Admin user management has no delete endpoint; financial history is not physically removed. There is no inquiry/SMTP module to harden in this source.

Retention is dry-run by default and uses the latest period across history. Renewal/canceled periods protect projects. Execution additionally needs RETENTION_EXECUTION_APPROVED=true and an explicit approved user-ID list, rechecked while holding the user lock. No scheduler/boot deletion is installed; no retention deletion was run during this phase.

## Explicit migration procedure

1. Schedule maintenance; stop checkout/AI producers and drain the independent worker. Inventory all active legacy jobs and unresolved payments. Confirm the target DB/role and migration journal, inspect schema drift and existing storage. Never point test runners at production.
2. Have the DB operator take an encrypted, access-controlled PostgreSQL backup, e.g. `PGSERVICE=nesomn pg_dump --format=custom --file=nesomn-before-integrity.dump`. Verify restore into a separately provisioned disposable database; listing the archive alone is not a restore test. Back up private storage and preserve ENCRYPTION_KEY.
3. Inject the intended DATABASE_URL securely, then run `bun --no-env-file --no-install --cwd api src/db/preflight.ts`. It only reports conflict/count inventory. Duplicate case-insensitive email, license or multiple active jobs requires manual reconciliation; never auto-dedup/drop/reset.
4. Apply the reviewed migrations with `bun --no-env-file --no-install --cwd api src/db/migrate.ts`. New0004/0005/0006 are additive. Original0000-0003 remain byte-identical. Run on a clone first, with the production schema checked separately. Do not run drizzle push/reset/seed. Historical snapshots already drifted before this phase; reconcile snapshot metadata before future schema generation.
5. Start the updated app/independent worker with the same DB/Redis/key and verify readiness/schema, negative permissions and synthetic staging flows. Backward rollback to old financial writers is unsafe after new ledger/account writes: restore a matched DB/storage/app snapshot through the DB operator if required, never reset volumes automatically.
