Scope: shared client sidebar/theme control, existing login/register, and signed-out workspace access. This extends the user's screenshots; store, editors, payment, queue, and admin implementation remain outside this revision.

## Implementation checklist
- Original black/white brand assets with 12px separation from the wordmark; collapse action in header.
- Search separated from compact pricing/login actions; no orphan collapse button below account actions.
- Real Radix theme radio menu with selected state, keyboard navigation, labels and persistent system/light/dark preferences.
- Reuse existing Button, Input, dropdown components and shared monochrome/orange semantic tokens; no dependencies added.
- Login/register share a responsive studio composition, original brand, clear heading and focused form.
- Retain authored core copy, field validation, pending/error states, OAuth, identity/cache and safe returnTo handling.
- Signed-out workspace gets a contained access panel, heading, description, Login and catalogue link; preserve loading/retry/authenticated branches.
- Controls at least44px, visible focus and associated labels. Existing4px spacing base; larger responsive page margins serve the requested separation.
- Production assets checked at360/390/768/1024/1440px in light/dark; check internal overflow, theme persistence, drawer focus trap/recovery and failed sign-in.
- No fabricated content, mock success, credentials, or business API changes.

References: incumbent shell/auth/PageState, existing shared theme, and user screenshots as negative layout references. No broad survey of unrelated page styling was performed. Admin retains its native theme selector; browser helper supports both its control and the client Radix menu.

## Stack decision
shadcn/ui normally uses Tailwind for styling; Radix provides accessible behavior. Existing local components already use Radix and Tailwind. This revision reuses those primitives and adds scoped semantic CSS; it does not remove Tailwind across the platform.
